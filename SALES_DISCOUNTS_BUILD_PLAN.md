# Sales discounts: implementation plan and contract

Approved design: `PROPOSAL_SALES_DISCOUNTS.md` (final, PR 25 and PR 26) and `BUSINESS_RULES.md` section 13C. All four small confirmations are APPROVED by the owner (2026-11-17): **A** two forward-only migrations, **027 for `sale_items`** and **028 for `print_sales`**; **B** when correcting a service sale the replacement keeps the ORIGINAL list price (a correction must not silently use a newer service price or create a new price reduction) - the same rule is applied to goods lines of the same product; **C** goods and services bought in one visit stay separate records through the existing POS and Services workflows, each with its own discounts, NO combined checkout; **D** NO new service-return feature (services keep void and "correct this entry", preserving the amount actually paid).

## Data model (frozen; migration agent M builds exactly this)
Both tables get these columns (all INTEGER NOT NULL, existing rows get the stated value):
- `list_unit_price_cents` (= `unit_price_cents` for existing rows; the normal price at the time of the sale: product `sell_price_cents` or service type `price_cents`, or, for Telecom lines, equal to `unit_price_cents`);
- `unit_discount_cents` (typed per unit; 0); `line_discount_cents` (= unit x qty; 0); `price_reduction_cents` (0); `bill_discount_cents` (the line's whole-bill share; 0).
Checks on both: `revenue_cents = qty * unit_price_cents - line_discount_cents - bill_discount_cents`; `revenue_cents >= 0`; `unit_discount_cents BETWEEN 0 AND unit_price_cents`; `line_discount_cents = unit_discount_cents * qty`; `price_reduction_cents = qty * max(0, list_unit_price_cents - unit_price_cents)` (write `CASE WHEN`/`MAX` in SQL); `list_unit_price_cents >= 0`; `bill_discount_cents >= 0`; plus every existing check (sale_items: `returned_qty BETWEEN 0 AND qty`, `line_type`, `UNIQUE (sale_id, line_no)`, cost checks; print_sales: `cogs_cents = qty * unit_cost_cents`, date checks, status/void rules, `client_ref UNIQUE`, service-type FK).
Telecom protection: a BEFORE INSERT trigger on `sale_items` refuses any non-zero `unit_discount_cents`, `line_discount_cents`, `price_reduction_cents`, `bill_discount_cents` and any `list_unit_price_cents <> unit_price_cents` when the owning sale has `book = 'telecom'` (every segment). `print_sales` is Shop-only by construction.
Immutability: `trg_sale_items_immutable` and `trg_print_sales_immutable` are extended so the new columns are immutable after insert. No new column on `sales` (the sale's gross/discount/bill totals are derived by summing its lines).
Rebuild pattern: 015/023/025 (`PRAGMA defer_foreign_keys = ON`, TEMP copy, keep `sqlite_sequence`, DROP, CREATE, INSERT with the same ids, restore the sequence, re-create EVERY index and trigger from `sqlite_master` of a schema-26 database, never from memory, guards that abort on any row difference, foreign-key violation, or an object set that is not exactly old + new). Objects: `sale_items`: indexes `idx_sale_items_product`, `idx_sale_items_sale`; triggers `trg_sale_items_book_mismatch`, `trg_sale_items_extra_cost_immutable`, `trg_sale_items_immutable`, `trg_sale_items_no_delete`, `trg_sale_items_segment_matches`; FK child `sales_return_items`; triggers on other tables that read it (`trg_sales_return_items_exceeds`, `trg_sales_return_items_extra_exceeds`, `trg_sales_return_items_mismatch`, `trg_sales_returns_void_effects`, `trg_stock_movements_return_restock`, `trg_stock_movements_return_reversal_cap`) must stay present and behave identically. `print_sales`: indexes `idx_print_sales_business_date`, `idx_print_sales_posted_at`, `idx_print_sales_type_date`; triggers `trg_print_sales_business_date_immutable`, `trg_print_sales_day_closed`, `trg_print_sales_day_closed_void`, `trg_print_sales_future_date`, `trg_print_sales_immutable`, `trg_print_sales_no_delete`, `trg_print_sales_posted_at_immutable`, `trg_print_sales_type_active`, `trg_print_sales_void_requires_reversal`; the cash-entry triggers keyed on `ref_table = 'print_sales'` and the `corrections` link keep working.

## API contract (frozen; stage 2 packages code against it)
**POS `POST /sales`**: each item gains optional `unitDiscountCents` (integer >= 0, default 0, the discount PER UNIT); the body gains optional `billDiscountCents` (integer >= 0, default 0, ONE whole-bill amount for the Shop part of the cart). `unitPriceCents` is the typed price P (as today); the list price L is read by the server from the product (`sellPriceCents`) at sale time; for a Telecom line L = P. Server rules: a Telecom line with `unitDiscountCents > 0` -> 400 `DISCOUNT_NOT_ALLOWED` (field `items.N.unitDiscountCents`); `billDiscountCents > 0` on a cart with no Shop goods lines -> 400 `DISCOUNT_NOT_ALLOWED`; `unitDiscountCents > unitPriceCents` -> 400 `DISCOUNT_EXCEEDS_AMOUNT` (field on the item); `billDiscountCents > S` (Shop subtotal after the per-unit discounts) -> 400 `DISCOUNT_EXCEEDS_AMOUNT` (field `billDiscountCents`); the bill discount is allocated over the SHOP lines only by the approved largest-remainder method (ties to the lower line number) and never touches Telecom sales; all arithmetic and refusals happen before anything is saved (atomic, idempotent by clientRef as today). Per line the server stores: `list_unit_price_cents`, `unit_discount_cents`, `line_discount_cents = unit x qty`, `price_reduction_cents = qty x max(0, L - P)`, `bill_discount_cents` (share), `revenue_cents = qty x P - LD - share` (the amount paid, = the cash). **Response**: each sale item gains `listUnitPriceCents, unitDiscountCents, lineDiscountCents, priceReductionCents, billDiscountCents, grossCents (= qty x max(L,P)), discountCents (= PR + LD + share)`; each sale gains `grossCents`, `discountCents`, `billDiscountCents` (sum of shares), `priceReductionCents`, `lineDiscountCents`; `revenueCents`/`totalCents` stay the net amounts. Warnings `PRICE_BELOW_MINIMUM` / `PRICE_BELOW_COST` are judged on the line's final net amount in integers (`net < qty x minimum`; `net < qty x unit cost`), never blocking; Telecom keeps today's behaviour.
**Returns**: `mulDivRound(net revenue of the line, q, qty)` with the exact remainder for the final return (the existing C5 code already reads `revenue_cents`; verify, do not duplicate), cost and extra cost as today.
**Services `POST /print-sales`**: body gains optional `unitDiscountCents` and `billDiscountCents` (the whole-sale discount, the single line takes all of it); `unitPriceCents` is the typed price (default the service type's price); L = the service type's `price_cents` at sale time; same errors `DISCOUNT_EXCEEDS_AMOUNT` (per unit > price; bill > `qty x P - LD`). Response gains the same fields (`listUnitPriceCents, unitDiscountCents, lineDiscountCents, priceReductionCents, billDiscountCents, grossCents, discountCents`); `unit_cost_cents`/`cogs_cents` unchanged. Warning `PRICE_BELOW_COST` on the net (`net < qty x unit cost`).
**Corrections**: sales and print-sale correction bodies carry the same discount fields; the replacement keeps the ORIGINAL list price: for a service the original's `list_unit_price_cents`; for a goods line of the SAME product the original line's list price; a new product uses today's price; implemented through an internal optional parameter of the create functions (NOT in the public HTTP create body) exactly like the commission-rate preservation of reloads; `comparison` gains original/replacement `discountCents` and `netCents`; everything else (atomicity, guards, audit) unchanged.
**Reports**: Shop only; fields `grossSalesCents`, `discountsCents`, `priceReductionsCents`, `lineDiscountsCents`, `billDiscountsCents`, `netSalesCents`, each also for `products` and `services`; `Gross - Discounts = Net` and `Net = existing Shop revenue (goods + services)` for every period; voided records excluded; Telecom reports unchanged (discounts always 0, no new lines).
Error codes: `DISCOUNT_NOT_ALLOWED` (400), `DISCOUNT_EXCEEDS_AMOUNT` (400); database aborts of the new triggers/checks must be mapped to these (or a clean 409), never a 500.
